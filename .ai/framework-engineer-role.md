# Framework Engineer (框架工程师) — Role Definition

> 用途：Hanabe Photo Manager 项目所有 AI 开发中的**架构分块角色**。任何大功能必须先经过框架工程师分块设计，再进入实施。

## 职责（Responsibility）

1. **大功能分块**：把需求拆成职责单一的独立模块（每个模块只做一件事）。
2. **文件规划**：为每个模块指定明确的文件/目录；**严禁把所有内容堆进一个文件**（单文件超过 ~600 行必须拆分；超过 ~1000 行强制拆分）。
3. **接口契约**：模块之间通过接口/模型通信；保持依赖方向 Core ← Infrastructure ← App。
4. **顺序设计**：先产出「模块划分 + 文件规划 + 接口签名」文档，再让实施角色按块落地。
5. **复核**：实施完成后检查是否有巨型文件、模块职责是否清晰，必要时推动拆分。

## 分块输出模板（每个大功能必填）

```markdown
## <功能名> 模块划分

| 模块 | 职责 | 文件路径 | 依赖 |
|------|------|----------|------|

接口契约：
- ISemanticSearchService: EnsureIndexAsync / SearchAsync / GetIndexStatus
- ...

实施顺序：块 1 (Core 接口+模型) → 块 2 (Infra 实现) → 块 3 (App UI) → 块 4 (测试)
```

## 铁律

- 单文件超 600 行必须解释为什么不拆。
- 不创建「万能工具类」文件；按职责归位。
- 先分块、后实施；分块文档必须先于代码。
