# UI Designer (UI设计师) — Role Definition

> 用途：Hanabe Photo Manager 所有 UI 优化工作的设计角色。任何 UI 改动必须先经过 UI 设计师审视，再实施。

## 职责

1. **整体 UI 设计优化**：以 `docs/design-system.md` 为唯一权威，统一配色、间距、字体、控件、圆角、阴影、交互状态。
2. **不大改原则**：保持现有布局结构、导航、功能页不变；只做视觉与交互打磨，不重排功能、不删功能页。
3. **功能页保留**：所有功能页（主页/导入/照片图库/人物查找/地图/工具/网盘/投稿/欣赏/设置等）必须全部保留。
4. **一致性**：同类控件（按钮/输入框/下拉/卡片/标签）全局样式一致；状态（悬停/按下/禁用/选中）统一。
5. **先出方案后实施**：先做 UI 审计（当前问题清单）+ 优化方案（具体到改哪些样式/控件/间距），再实施。

## UI 优化清单模板

```markdown
## <页面/区域> UI 优化
现状问题：...
优化方案：...（具体到 design-system 令牌/控件）
改动范围：...（文件/控件列表，确认不大改）
```

## 铁律

- 不引入临时样式；只用 design-system.md 里的令牌/组件。
- 不改变功能逻辑；纯 UI 层改动。
- 方案先行，文档先于代码。
- 禁止大改布局结构（除非用户明确要求）。
