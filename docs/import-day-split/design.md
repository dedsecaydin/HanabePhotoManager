# 导入：同一天分段放文件夹（HANABE-IMPORT-DAY-SPLIT）

设计稿：画布 Windows 页“Windows · 同一天分段放文件夹”（win/ImportSplit）和“Windows · 导入检查确认”（11.04 卡片上的徽章）。macOS 版用同一结构，尺寸按 macOS 规范。
业务逻辑只写在 HanabePhotoManager.Shared；Windows、Mac 两端只做界面。

## 要解决的事
同一天拍了不止一场（例如上午婚礼、晚上另一单），中间停了很久。导入时应该自动分成几个日期文件夹；用户也可以手动改回“都放进同一个文件夹”。

## 判定规则
1. 时间来源：EXIF DateTimeOriginal（含亚秒、偏移）；没有就用文件修改时间。日期归属规则不变（文件夹名后 4 位 MMDD，否则修改时间）。
2. 以“组”为单位：RAW + 同名 JPG、视频 + 封面等配对组整体参与，组时间取组内最早时间；一组永远不拆开。
3. 同一天里按时间排序，相邻两组间隔 ≥ 阈值就切开。阈值默认 2 小时，可选 1 / 2 / 3 / 4 小时（导入设置）。
4. 少于 5 组的段不单独成段，并入时间更近的相邻段（避免零星试拍、测光）。
5. 设置项“同一天有间隔时自动分文件夹”，默认开启。关闭时行为与现在完全一样。

## 文件夹与命名
- 每段对应一个日期文件夹决定，复用现有 ImportDateFolderDecision / ImportDateFolderPreflightService（处理方式：使用原文件夹 / 改名 / 新建；备注）。
- 当天已有文件夹时：第 1 段默认“使用原文件夹”，其余段默认“新建”。
- 新建段的备注自动填：开始时间 < 12:00 → 上午，12:00–18:00 → 下午，≥ 18:00 → 晚上；同一天重名加 2、3（晚上2）。用户可直接改。文件夹名沿用现有格式 `M月\M.DD_备注`，非法字符照现有 NormalizeRemark 处理。
- 两段最终指向同一路径时视为合并，不报错。

## 界面（检查确认页）
- 日期卡片：多于 1 段时右上加徽章“分成 N 段 · X 小时间隔 ›”；“放到”下面每段一行：色点 + 文件夹名 + 时间范围 + 组数 + （新建/原文件夹）。
- 点徽章进入当天详情（win/ImportSplit）：
  - 顶部一句话“这一天拍了 N 段，中间停了 X 小时 Y 分”+ 分段开关“分成 N 个文件夹 / 都放进一个文件夹”。
  - 06:00–24:00 时间轴：每段一种颜色的密度柱，间隔区域斜线填充并标注时长。
  - 每段一张卡：段号、时间范围、组数、4 张缩略图 + 剩余数、分类构成；右侧“放到”文件夹名 + 备注输入（处理方式下拉同现有）。
  - 相邻两段之间一个按钮“这两段放一起”（手动合并相邻段）；合并后可撤销（复用导入整理的撤销栈）。
  - 选“都放进一个文件夹”：回到单张日期卡片，按现在的逻辑处理。
- 底部汇总“本次导入共 N 个目标文件夹”，“开始导入”只在所有段的决定都有效时可用（沿用现有校验）。
- 修改阈值或开关后，检查页的日期方案自动重算（沿用 ScheduleInlineDatePlanRefresh）。

## 不变的
- “拍摄场次”（30 分钟虚拟分组，SessionPlanner / JsonSessionStore）照旧，不受影响，也不移动文件。
- 「修后」永远不写入；查重、校验后移动、恢复记录逻辑不变。
- 测试库不得指向真实库 \\Desktop-eqvlo2n\拍照。

## 需要的测试（Shared 层）
- 2 段（间隔 4h50m）→ 2 个决定；阈值改 6 小时 → 1 个。
- 配对组跨阈值不拆开；段 < 5 组并入较近段。
- 当天已有文件夹：第 1 段用原文件夹，第 2 段新建“晚上”；重名加序号。
- 关闭开关 → 结果与旧逻辑逐项相同。
- 手动“这两段放一起”与“都放进一个文件夹”后，导入目标路径正确，可撤销。

## 实现状态（2026-11-08）
- 已实现：Shared 逻辑、Windows 检查页、Mac 检查页、导入设置开关与小时数、真实导入按段落盘（沙盒验证）。
- 与设计稿不同：没有单独的“当天详情页”和 06:00–24:00 时间轴；改为每段一张日期卡片（色点、时间、间隔、合并 / 都放一起按钮）。如果要完全按 win/ImportSplit 做详情页，在此基础上加一个页面即可，数据都已在 `ImportDateFolderDecision` 上。
- 拍摄时间：先用文件修改时间，Windows 后台补读 EXIF 后若分段变化会静默重建；Mac 目前只用修改时间。
