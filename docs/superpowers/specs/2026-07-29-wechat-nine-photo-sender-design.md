# 微信九图批量发送设计

## 目标

在 Hanabe Photo Manager 的“图片小工具”中增加“微信发送”子功能。用户拖入照片后，应用通过用户本机已登录的微信桌面客户端，把原始文件以文件附件形式发送到指定个人、普通群聊或“文件传输助手”。队列按顺序切成每批 9 张，末批不足 9 张时发送剩余文件；明确失败时只重试缺失文件。

## 范围与安全边界

- 仅支持 Windows 桌面版微信；其他平台显示“不支持桌面自动发送”，不暴露开始按钮。
- 不调用非官方微信 API，不读取 Cookie，不绕过登录、验证码、安全提示或客户端限制。
- 原图以 `CF_HDROP` 文件附件投递，源路径直接指向原文件，不转码、不压缩、不制作临时副本，发送前后源文件大小、修改时间和可选 SHA-256 快照不得改变。
- 首次解析目标聊天后，必须由用户在 Hanabe 中二次确认微信标题和目标类型；确认只针对发送目标，不是开发过程确认。
- 不在后台静默发送。选择聊天、投递、发送和结果验证期间微信必须在前台。
- 用户可随时取消；取消后不再开始新动作、后续批次或重试。已经交给微信的发送无法撤回。
- 不把用户的照片、聊天内容、联系人列表或日志上传到外部服务。

## 与现有图片小工具的集成

现有 `CompressionPage` 已用顶部横向选项和平滑淡入在“批量压缩 / 拼图 / 批量水印”之间切换。“微信发送”沿用同一入口和 180 ms 切换动效，但使用独立的 `WeChatSenderViewModel` 和视图：

- `ImageToolMode` 增加 `WeChatSend`，`ToolModes` 增加“微信发送”。
- 微信队列不复用 `CompressionViewModel.Items`、输出目录、压缩进度或 `StartCommand`，避免切换子功能后残留状态被误发送。
- 拖放事件按当前模式路由：微信模式只把符合图片发现规则的真实文件加入微信队列；其他模式保持原行为。
- 复用 `ImageInputDiscovery` 的扩展名、递归扫描和按规范化完整路径去重规则。目录扫描可取消，并在后台执行，不能阻塞 UI 线程。
- 切走微信页面不等于取消。发送中禁止切换子功能，或先显式取消并等状态机进入稳定状态后才允许切换。

## 界面

页面包含：

1. 拖放/选择照片区，显示顺序、文件名、原始大小、批次号和单项状态；支持发送前重排、移除、清空。
2. 目标聊天输入框，支持联系人、群聊和“文件传输助手”。
3. 微信状态：未检测、未启动、正在启动、待登录、已在前台、目标待确认、可发送、发送中、已暂停、已取消、已完成。
4. “检测并打开微信”“定位目标”“确认此目标”“开始发送”“取消”按钮。
5. 发送进度：总数、当前批次、已成功、明确失败、结果不确定；进度只按已确认成功项增长。
6. 本地会话日志和失败项列表。日志不记录聊天内容、联系人列表或图片内容，只记录时间、队列项 ID、文件名、目标显示名、批次、尝试次数、阶段和状态。

“确认此目标”区域必须同时显示从微信实时读取的聊天标题、目标类型和微信窗口截图缩略图或醒目的“请在微信中核对”提示。目标名称被编辑、微信进程重启、窗口句柄变化或用户重新定位目标后，旧确认立即失效。

## 模型与职责

- `WeChatSenderViewModel`：页面状态、命令、队列展示、目标确认和取消。
- `WeChatSendQueueService`：纯状态机、分批、重试、幂等和进度，不直接操作窗口。
- `IWeChatDesktopGateway`：进程发现、启动、前台门禁、UI Automation、文件投递、发送和结果探测。
- `IWeChatExecutableLocator`：仅负责解析、验证和返回候选微信可执行文件。
- `IWeChatSendLog`：追加式本地日志；写入失败不能导致重发，改为显示“日志写入失败”并暂停。

所有网关方法都接收 `CancellationToken` 和有界超时，返回结构化阶段结果，不以异常文本驱动状态机。

## 微信定位、启动与进程身份

1. 先枚举进程映像名 `Weixin.exe`、`WeChat.exe`，只接受有可见顶层窗口或能在等待期内创建顶层窗口的进程。
2. 未运行时按以下顺序解析：
   - Hanabe 设置中由用户选择并保存的绝对路径；
   - `HKCU`、`HKLM` 的 `App Paths\Weixin.exe` 与 `App Paths\WeChat.exe`（同时检查 32/64 位注册表视图）；
   - 微信官方安装项的 `InstallLocation`；
   - `%ProgramFiles%`、`%ProgramFiles(x86)%`、`%LocalAppData%` 下已知微信目录。
3. 候选必须是存在的本地文件，规范化后文件名为 `Weixin.exe` 或 `WeChat.exe`。自动发现到多个不同路径时不猜测，显示路径让用户选择并持久化。
4. 使用 `ProcessStartInfo.UseShellExecute = true` 启动。启动成功只代表进程已创建，不代表可发送；最长等待 20 秒，每 250 ms 重查一次可见顶层窗口。出现登录窗时进入“待登录”，不继续发送。
5. 启动器进程可能把窗口移交给已有或新建子进程，因此建立“本次微信进程集合”：启动前后的合法微信映像进程、其创建时间和可执行路径必须匹配已确认安装路径。不能只信任 `Process.Start` 返回的 PID。
6. 获得顶层窗口后记录句柄、PID、进程创建时间和可执行路径。进程退出、重启或句柄重建后必须重新定位目标并重新二次确认，不能沿用旧确认。

自动定位失败时显示已检查位置和失败原因，并提供“选择微信程序”按钮；不尝试下载或安装微信。

## 前台窗口 PID 门禁

每个有副作用的动作前后都执行同一门禁：

1. 确认目标微信进程仍存活，PID、创建时间、映像路径属于“本次微信进程集合”。
2. 确认顶层窗口属于该 PID，且不是登录窗、更新窗、安全提示、文件选择器或其他微信辅助窗口。
3. 若最小化，调用 `ShowWindow(SW_RESTORE)`，等待窗口可交互。
4. 请求置前后读取 `GetForegroundWindow`，再用 `GetWindowThreadProcessId` 校验前台句柄 PID。
5. 前台 PID 必须属于已验证微信进程集合；仅窗口标题相同不算通过。
6. 校验当前聊天标题仍等于已确认目标，并且目标确认令牌仍有效。

该门禁在定位聊天、清空自动化搜索文本、投递附件、验证预览、执行发送、验证气泡和每次重试前分别执行。任何一步失败立即进入 `Paused`，不按键、不投递、不发送、不重试，等用户恢复后从无副作用的校验阶段继续。

## 目标聊天定位与二次确认

网关只用 Windows UI Automation 元素和模式定位微信搜索框、候选列表、聊天标题与输入区，不使用固定屏幕坐标。

- 输入用户填写的目标名称后，仅打开用户明确选择的候选。多候选、同名联系人、同名群聊或目标类型不可读时，停在微信界面让用户手动选中。
- Hanabe 从当前聊天区重新读取标题和可识别的目标类型，生成包含进程身份、窗口句柄、标题、目标类型和确认时间的目标确认令牌。
- 即使标题与输入完全一致，首次仍必须由用户点击“确认此目标”。未确认时“开始发送”不可用。
- 每批投递前、按发送键前和发送后都重新读取标题。标题、目标类型、进程身份任一变化，确认令牌失效并暂停。
- “文件传输助手”走相同流程，不写死坐标或跳过确认。
- 不读取或保存聊天消息正文；结果探测仅访问本次发送后新增的文件附件消息元素。

## 发送前快照与队列

每个队列项拥有不可变 `QueueItemId`，并在开始前记录规范化完整路径、显示文件名、长度、最后写入时间。发送前再次核对文件存在且长度和最后写入时间未变化；发生变化时该项标记为 `Changed`，暂停让用户重新确认。

状态包括：

`Pending`、`Staging`、`ReadyToSend`、`Sending`、`Sent`、`Failed`、`Ambiguous`、`Changed`、`Canceled`。

分批规则：

- 按用户当前排序顺序，每批恰好取最多 9 个仍为 `Pending` 的项目；最后一批发送余数。
- 同一批内展示文件名必须唯一。重名项移到后续批次；若重名数量导致仍冲突，则继续拆批，确保同批验证能由文件名唯一映射。
- 批次形成后不因重试重新编号；明确缺失项构成该批的重试子集，不把后续待发项补进重试。
- 单实例、单发送任务串行运行；禁止并行控制微信。

## 文件投递与输入框空白检测

每批开始前必须同时满足：

1. 前台 PID 和目标门禁通过；
2. 微信输入框可读、可编辑且当前为空；
3. 输入区没有附件预览或未发送草稿；
4. 记录发送前消息列表锚点、已有同名文件气泡数量和时间戳，后续只检查锚点之后的新元素。

如果输入框已有用户文本、附件或草稿，立即暂停并提示用户自行处理；自动化不得覆盖、发送或删除用户草稿。

投递使用包含本批原始绝对路径的 `CF_HDROP` 数据，通过微信输入区可识别的文件粘贴/投递动作加入附件；不把图片解码到剪贴板。投递后必须验证：

- 输入区出现与本批数量一致的附件预览；
- 每个预览文件名能与本批唯一映射；
- 当前目标和前台 PID 仍通过门禁。

预览数量或名称不一致时不按发送键，状态为 `Ambiguous` 并暂停。只有完整预览校验通过后才执行一次发送动作。

## 成功检测

单张文件只有同时满足以下条件才标记 `Sent`：

1. 发送后输入区对应附件预览消失，且输入框无本次自动化残留；
2. 发送前锚点之后新增的外发文件消息中包含对应唯一文件名；
3. 对应消息的上传/发送状态已结束，且在验证窗口内没有失败或重试角标；
4. 当前聊天标题、目标类型、窗口和 PID 仍匹配目标确认令牌。

输入框空白只说明微信消费了输入，不能单独判定成功。历史同名气泡、发送前已有消息和其他聊天中的同名文件都不能作为成功证据。验证应等待有界稳定窗口，例如每 250 ms 轮询、最长 15 秒，并要求成功状态连续稳定两次；超时不等于明确失败。

结果分类：

- `Sent`：四项证据全部成立。
- `Failed`：本次新增消息存在微信明确失败角标，或批次中能明确映射的文件缺失而其他文件已稳定成功。
- `Ambiguous`：元素不可读、上传仍未结束、超时、气泡映射不唯一、输入区状态与气泡矛盾，或无法确认失败角标。

## 有限且去重的重试

- 首次发送不计入重试次数；每个文件最多再重试 3 次，重试前分别等待 1 秒、2 秒、4 秒。
- 只将本批中明确 `Failed` 或有充分证据确认缺失的文件放入重试子集。`Sent`、`Ambiguous`、`Changed` 和 `Canceled` 项绝不自动重发。
- 每次重试重新检查源文件快照、前台 PID、目标令牌、空输入框和发送前消息锚点。
- 已找到并稳定确认成功气泡的文件永久记为 `Sent`，即使同批其他文件失败也不会重发。
- 三次重试后仍明确失败，保留 `Failed` 并继续下一批前要求用户选择“跳过失败继续”或“结束”；不得自动把失败项无限循环。
- 任何无法判断的结果设为 `Ambiguous` 并暂停人工处理。用户只能选择“我已核对为成功”“确认未发送，允许重试”或“结束任务”；重新发送必须是显式选择。

状态机以 `QueueItemId + 尝试序号` 记录每次调用。日志写入或 UI 刷新失败不得回滚 `Sent` 状态，也不得触发重复调用。

## 取消与恢复

- 取消令牌在目录发现、等待微信启动、UI Automation 等待、批次间等待、结果轮询和退避等待中生效。
- 按下取消后立即禁止新的投递和发送动作，状态进入 `CancelRequested`，待当前不可中断的 UI Automation 调用返回后进入 `Canceled`。
- 尚未投递的项目标记 `Canceled`；已经稳定确认成功的项目保持 `Sent`。
- 已投递到输入区但尚未按发送键时，禁止用 `Ctrl+A/Delete` 等盲操作清理，因为可能删除用户内容；暂停并提示用户在微信中核对/清理，相关项记为 `Ambiguous`。
- 已按发送键但尚未完成验证时，继续做只读验证直到有界超时，不再重试；能证实成功则记 `Sent`，否则记 `Ambiguous`。
- 恢复只允许从无副作用的前台/目标/输入区校验重新开始。进程重启或目标确认失效后必须重新定位并确认。

微信退出、崩溃、Windows 锁屏、弹出安全提示、前台被切走或 UI Automation 元素缺失时暂停。微信版本变化导致元素不可识别时显示具体阶段和原因，不回退到固定坐标盲点。

## 日志与隐私

日志采用追加写入，每条至少包含：

- UTC 时间与本地显示时间；
- 会话运行 ID、队列项 ID、批次和尝试序号；
- 文件名、长度（不默认记录完整路径）；
- 已确认目标显示名和目标类型；
- 阶段、结构化结果码、是否用户判定。

不记录聊天正文、联系人列表、剪贴板内容、图片缩略图或访问令牌。日志中的目标名和文件名属于本地隐私，设置中可关闭持久日志并清除历史。日志轮转并限制总大小。

## 测试

自动化测试全部使用替代网关，绝不向真实微信发送消息：

- 分批：0、1、8、9、10、18、19 张；同名文件跨批；保持用户排序。
- 原图：网关收到的是原始绝对路径；发送前后长度、时间和哈希不变；不产生压缩或临时副本。
- 启动定位：配置路径、两种注册表视图、安装位置、多个候选、无安装、登录窗、20 秒超时、启动器 PID 移交。
- 前台门禁：最小化恢复、置前失败、前台 PID 不匹配、同名非微信窗口、进程重启、句柄变化、辅助窗口误选。
- 目标确认：精确标题仍需确认、同名候选、手动选中、标题或类型变化、确认令牌失效。
- 输入区：发送前非空、已有草稿/附件、9 个预览完整、预览缺失、预览重名、投递后目标变化。
- 结果探测：输入区已空但无气泡、历史同名气泡、成功气泡、明确失败角标、上传未结束、超时、部分成功。
- 重试：只重试明确失败子集；首次加最多三次重试；1/2/4 秒退避；成功项永不重发；歧义暂停。
- 取消：发现阶段、启动等待、投递前、投递后发送前、发送后验证中、退避中取消。
- 日志：不含正文/完整路径；日志失败不导致重发；轮转。
- UI：横向入口、独立队列、目标二次确认、实时进度、取消、失败/歧义列表和无障碍键盘操作。

可选的真实客户端冒烟测试必须由开发者显式启用，目标限定为自己的“文件传输助手”，默认跳过，且不能纳入普通测试运行。

## 非目标

- 不实现群发营销、联系人抓取、自动加好友、验证码处理、后台静默发送或撤回消息。
- 不保证绕过微信客户端自身的文件大小、频率、登录或安全限制。
- 不在本阶段支持 macOS/Linux 微信自动化，不接入 Docker、外部 API 或云端发送服务。
