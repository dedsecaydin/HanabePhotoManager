# `src/` 可维护性注释与等价精简设计

## 1. 背景与目标

Hanabe Photo Manager 的生产代码已覆盖照片导入、图库、元数据、地图、人物、主题、安装与后台任务等多条工作流。随着功能增长，维护者需要更快地理解代码职责、定位修改入口，并在不破坏现有功能的前提下降低重复和复杂度。

本任务只处理 `src/` 下的生产代码，目标包括：

1. 为公共类型、公共接口、核心工作流和困难逻辑补充高价值中文注释与批注。
2. 精简重复实现、过长职责块和确认无引用的生产代码。
3. 保持现有 UI、Binding、Command、动画、主题、公开接口、数据格式和操作结果不变。
4. 提供面向维护者的代码阅读与修改指南，以及面向使用者的完整使用说明。

## 2. 非目标

- 不处理 `tests/` 与 `installer/` 中的代码注释或重构。
- 不增加新产品功能，不改变业务规则。
- 不重新设计 UI，不调整视觉风格。
- 不以压缩行数为目标，不采用降低可读性的表达式堆叠或过度抽象。
- 不删除仅凭命名判断为“可能无用”的代码。

## 3. 权威来源与约束

实施时遵循以下优先级：

```text
当前仓库与运行行为
    > 当前测试与项目文档
    > 历史交接与旧设计稿
```

WPF 相关代码必须保持：

- Binding 路径和更新行为不变。
- Command 名称、CanExecute 与执行结果不变。
- 事件处理器连接、导航流程和窗口生命周期不变。
- Light/Dark 资源键契约和主题切换行为不变。
- 动画时序、可中断性与最终视觉状态不变。
- 图库虚拟化、缩略图优先级、选择、滚动和缓存行为不退化。

## 4. 采用方案

采用“分层精简与注释”，按依赖方向推进：

```text
基线清单
  ↓
Core
  ↓
Infrastructure
  ↓
App 服务与 ViewModel
  ↓
App XAML 与资源
  ↓
全量验证与维护文档
```

每层都必须保持可构建、可测试、可审查；不得一次性推倒重写。

## 5. 注释策略

### 5.1 XML 文档注释

以下成员应优先使用中文 XML 文档注释：

- 公共和内部核心类型。
- 领域接口、服务接口、记录和枚举。
- 公开方法、关键异步入口与重要属性。
- 其调用约束无法从签名直接判断的成员。

按实际需要使用 `<summary>`、`<param>`、`<returns>`、`<exception>` 与 `<remarks>`；没有信息增量时不堆砌模板化标签。

### 5.2 行内批注

行内批注只解释“为什么”，重点覆盖：

- 领域不变量和兼容约束。
- 线程、Dispatcher、取消、竞态与最新请求优先策略。
- 文件安全、原子替换、校验和恢复策略。
- 缓存键、生命周期、淘汰和性能权衡。
- WPF 虚拟化、绑定或资源解析的非直观限制。
- 为兼容既有数据或行为而保留的特殊分支。

不注释赋值、循环、空值判断等显而易见语法。

### 5.3 XAML 批注

XAML 只在主要布局区、共享行为区和非直观兼容结构前添加短注释。注释不得改变资源查找、绑定、名称作用域或可视树结构。

## 6. 精简策略

允许的精简方式：

- 合并语义相同的重复方法与重复转换逻辑。
- 提取稳定、清晰且已有多处使用的公共辅助方法。
- 用 partial 文件或小型协作者拆分超大 ViewModel/服务的独立职责。
- 降低嵌套深度，使用清晰的提前返回。
- 合并重复资源或样式时保持资源键兼容。
- 删除经引用搜索、编译与测试共同证明无用的私有生产代码。
- 消除不必要的同步 I/O、重复枚举和重复计算，但保持结果和时序契约。

禁止的精简方式：

- 为减少文件数量而重新集中职责。
- 创建第二套服务、缓存、选择或主题系统。
- 擅自重命名公开接口、Binding 属性、Command 或资源键。
- 将可读逻辑压缩为复杂 LINQ、嵌套条件表达式或反射方案。
- 在缺乏回归证据时删除兼容分支。

## 7. 行为保护清单

修改前后都要提取并比对：

- 公开类型与方法清单。
- XAML Binding、Command 和事件处理器清单。
- 主题资源键清单。
- 关键序列化字段和配置键。
- 后台任务、取消令牌和进度更新入口。
- 导入、图库、查看器、地图、人物和设置的主要工作流。

任何差异必须能够证明是纯内部实现变化，否则回退该项精简。

## 8. 文档交付

新增或整理两份中文文档：

1. `docs/maintainer-guide.zh-CN.md`
   - 解决方案与依赖关系。
   - 功能到目录、类型和测试的定位表。
   - 常见修改任务的入口与安全边界。
   - WPF、异步、缓存、文件系统与主题维护规则。
   - 构建、测试、发布与故障诊断步骤。
2. `docs/user-guide.zh-CN.md`
   - 前置环境与首次启动。
   - 照片库、导入、浏览、人物、地图、工具和设置。
   - 支持格式、数据位置、备份建议与常见故障。

文档必须引用当前真实路径与行为，不从历史聊天推断功能。

## 9. 验证策略

### 每层验证

- 编译受影响项目。
- 运行相关测试项目。
- 检查新增警告、绑定错误和静态引用差异。

### 最终自动验证

```powershell
dotnet build HanabePhotoManager.sln -c Release /warnaserror
dotnet test HanabePhotoManager.sln -c Release --no-build
dotnet publish src/HanabePhotoManager.App/HanabePhotoManager.App.csproj -c Release -r win-x64
```

如正式文档规定专用发布脚本，则以正式脚本为准。

### 最终运行验证

- 启动、导航与退出。
- Light/Dark 主题及图标切换。
- 导入、取消、进度与摘要。
- 图库自然滚动、日期展开/收起、缩略图缩放与选择。
- 双击照片/视频查看器与右侧详情。
- 地图缓存、人物页、设置保存和外接设备提示。
- 小窗口、常见 DPI、长中文文本和空/错/加载状态。

## 10. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 注释与真实行为不一致 | 先读实现和测试，禁止从名称猜测 |
| 重构破坏 WPF Binding | 前后导出 Binding/Command/事件清单并比对 |
| 精简造成竞态或性能回退 | 保留取消与调度语义，针对关键流程做运行验证 |
| 删除实际仍被反射/XAML使用的代码 | 同时检查 C#、XAML、资源键、序列化和反射引用 |
| 大批改动难以审查 | 按层、小批次提交，每批可独立构建测试 |
| 覆盖用户现有修改 | 仅修改任务相关文件，逐文件检查当前差异 |

## 11. 完成标准

只有同时满足以下条件才可宣布完成：

- `src/` 中公共 API、核心工作流和困难逻辑已有准确、有信息量的中文注释。
- 已识别的重复与复杂实现完成等价精简，且没有为了行数牺牲可读性。
- 无未经证明的公开接口、Binding、Command、资源键或数据格式变化。
- Release 构建、全量测试和发布通过。
- 关键运行流程完成回归检查。
- 维护指南与用户说明已与当前实现核对。
- 所有修改均记录在项目变更日志中，且未混入无关工作区改动。
