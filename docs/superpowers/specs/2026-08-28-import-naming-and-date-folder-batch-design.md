# 导入命名与日期文件夹批量管理设计

## 背景

当前导入命名由自由模板控制，底层支持 `{seq}`、`{orig}` 和 `{date}`，但导入页面没有面向常用场景的直观选择。导入结束后的日期备注采用逐个弹窗处理；重命名函数在找不到目录时会直接返回，调用方仍可能显示成功。用户还反馈“保存备注”按钮文字在部分视觉状态下难以辨认。

## 目标

1. 在导入页面提供三种常用命名方式，并持久化上次选择。
2. 生成“顺序＋原名”文件名时使用 `JK0001（DSC_1234）.ARW` 格式，扩展名只出现一次。
3. 提供集中管理所有日期文件夹备注的页面，替代逐个弹窗。
4. 只允许编辑备注，日期部分保持只读，不执行跨日期或跨月份移动。
5. 让目录重命名的成功、失败和未执行状态反映真实文件系统结果。
6. 保证保存操作的文字在支持的主题与交互状态下清晰可读。

## 非目标

- 不修改日期值。
- 不移动日期文件夹到其他月份。
- 不改变照片分类、导入复制/移动、校验、续传或重复文件处理逻辑。
- 不删除现有高级命名模板能力。
- 不自动覆盖已存在的目标目录。

## 导入命名交互

导入页面增加“文件命名”选择器，提供以下三个预设：

| 选项 | 模板 | 示例 |
|---|---|---|
| 顺序命名 | `JK{seq}` | `JK0001.ARW` |
| 保留原名 | `{orig}` | `DSC_1234.ARW` |
| 顺序＋原名 | `JK{seq}（{orig}）` | `JK0001（DSC_1234）.ARW` |

选择立即成为后续导入使用的命名模板，并通过现有设置存储自动记住。重新启动应用后恢复上次选择。

现有自由模板输入保留在高级/自定义区域。若已保存模板不等于三个预设中的任意一个，界面显示“自定义”，且不改写用户模板。用户选择任一预设后才用对应模板替换当前值。

命名仍按当前分类内的自然顺序生成序号。媒体组的主文件和附属文件沿用当前组命名与扩展名冲突规则。文件名中的原始部分不包含扩展名，扩展名从源文件取得并仅追加在最终名称末尾。

## 日期文件夹管理页面

新增“日期文件夹管理”入口和页面。页面扫描当前照片库的月份目录，使用现有 `LibraryDateFolderService` 解析支持的日期目录格式，并集中展示：

- 日期（只读）；
- 当前备注（可编辑）；
- 当前完整文件夹名；
- 保存状态或错误信息。

页面支持：

- 编辑任意多行备注；
- 清空备注，使目录恢复为 `MM.DD`；
- 一次执行“保存全部更改”；
- 刷新目录列表；
- 在每一行显示未修改、已保存、失败或已失效状态。

批量保存只处理实际发生变化的行。单行失败不阻止其他行保存。完成后显示成功、跳过和失败数量，并保留失败行的编辑内容以便修正后重试。

导入完成后不再为每个日期连续弹出备注窗口。导入结果区域提供进入日期文件夹管理页的明确入口；页面打开时重新扫描，因此能包含本次导入创建的目录。

## 文件系统规则与错误处理

目录命名格式为：

- 无备注：`MM.DD`
- 有备注：`MM.DD_备注`

保存前对备注执行现有语义一致的清理：去除首尾空白、重复日期前缀和开头分隔符，并将 Windows 文件名非法字符替换为下划线。清理后的预览应成为最终目录名。

重命名服务返回结构化结果，而不是无结果的静默返回。至少区分：

- 成功；
- 无变化；
- 源目录不存在；
- 目标目录已存在；
- 权限或 IO 失败。

只有 `Directory.Move` 实际成功后才能显示“保存成功”。目标目录存在时不覆盖、不合并，保留源目录并提示冲突。保存过程中若目录已被外部移动或删除，将该行标记为已失效并允许刷新。

## 视觉与可访问性

页面复用现有设计令牌、输入框、表格/列表和主次按钮样式，不创建页面级颜色常量或第二套按钮模板。

“保存全部更改”及相关保存按钮必须使用共享主按钮的前景色契约。需要验证 Light、Dark 及项目支持的其他主题，并覆盖 Normal、Hover、Pressed、Keyboard Focus、Disabled。按钮提供清晰的自动化名称和键盘焦点；保存期间禁用重复提交，但文字仍保持可辨认。

## 架构与数据流

- Core 的命名格式化能力继续作为目标文件名的唯一生成规则。
- App 设置保存命名模板，并提供预设与模板之间的映射。
- 独立的日期文件夹条目 ViewModel 保存原路径、解析日期、原备注、编辑备注及行状态。
- 日期文件夹服务负责扫描、规范化目标名称与执行单次安全重命名。
- 页面 ViewModel 负责加载条目、收集已修改行、逐项调用服务和汇总结果。
- View 只负责布局、绑定、命令和可访问性，不在代码隐藏中决定文件系统行为。

## 测试与验证

测试驱动实现至少覆盖：

1. 三种预设生成预期文件名，尤其是 `JK0001（DSC_1234）.ARW`。
2. 预设选择在设置存储重启后保持。
3. 自定义模板加载后不会被错误归类或覆盖。
4. 日期目录扫描识别现有受支持格式及备注。
5. 添加、修改和清空备注产生正确目标目录名。
6. 未变化、源目录消失、目标冲突、IO/权限失败返回准确结果。
7. 批量保存部分成功时继续处理其他行，并汇总真实数量。
8. 导入完成流程不再创建逐日期弹窗链。
9. 主按钮内容继续绑定到可读的共享前景色资源。

最终执行 Release 解决方案构建和完整测试。用户界面还需人工检查导入页、日期文件夹管理页、键盘操作和全部支持主题；未实际完成的人工检查不得声称通过。

## 兼容与迁移

现有 `ImportNamingTemplate` 设置继续有效，不引入破坏性迁移。三个预设直接映射到模板字符串；其他值视为自定义。已有照片和日期目录不会在页面打开时自动改名，只有用户点击保存后才执行变更。
