# 绯夜蔷薇 · Hanabe 主题设计

日期：2026-08-29  
状态：已获用户设计确认，待实施计划  
适用项目：Hanabe Photo Manager

## 1. 目标

为 Hanabe Photo Manager 新增一套名为“绯夜蔷薇 · Hanabe”的完整浅色/深色主题，并加入一个可选显示的 Hanabe 角色助手。主题从用户提供的黑色、酒红色、蔷薇、蝴蝶、拍立得与相机闪光素材中提炼视觉语言，但不让角色装饰遮挡照片、降低高密度工作区效率或改变现有业务流程。

成功标准：

- 新增 `Hanabe.Light` 与 `Hanabe.Dark` 两个可即时切换并持久化的主题入口。
- 两个主题实现现有主题的完整资源键契约，所有常用控件状态均清晰可读。
- Hanabe 角色用于主题预览、角色档案、状态反馈和可收起的任务助手。
- 用户可以关闭所有角色内容；关闭后原有任务、进度和状态信息仍可完整使用。
- 图库、照片查看器和高密度工具区不被持续角色插画覆盖。

## 2. 已选方向与备选方案

设计阶段比较了三档素材露出强度：

1. 克制装饰：角色只出现在主题选择页，工作区仅使用酒红色和蔷薇纹样。
2. 角色增强：图库保持安静，角色服务于状态、主题预览和任务反馈。
3. 沉浸主题：首页与侧栏持续出现大幅角色和装饰边框。

用户选择方案 2。它能建立明确的 Hanabe 角色识别，同时不会让照片管理界面变成海报或游戏启动器。角色档案、状态陪伴和互动彩蛋三类内容全部纳入范围，但都受一个总开关控制。

## 3. 视觉系统

### 3.1 深色模式

深色模式以墨黑、黑莓棕和低亮度酒红表面构成层级。高饱和红仅用于主操作、选中指示、进度和特殊状态，不作为大面积背景。蔷薇纹样只允许以低透明度出现在非内容关键区域。

### 3.2 浅色模式

浅色模式使用暖象牙白、灰粉表面、深酒红文字强调和柔和边界，不采用深色主题的简单反相。照片缩略图周围保持中性，避免暖色表面影响用户对照片色彩的判断。

### 3.3 资源约束

- 原始颜色只进入 `Themes/Colors/Colors.Hanabe.Light.xaml` 与 `Colors.Hanabe.Dark.xaml`。
- 主题入口复用现有 Brushes、Tokens、Typography、Motion 和 Controls 组合机制。
- 不新增页面级颜色、圆角、阴影、字体或动画常量。
- Light 与 Dark 必须导出同名、同类型资源。
- PhotoViewer 继续使用既有固定深色画布，不套用角色背景。

## 4. 素材与角色内容

角色名为 Hanabe，主题全名为“绯夜蔷薇 · Hanabe”。用户提供的素材按用途拆分为：

- 表情素材：用于空状态、处理中、完成、取消和错误反馈。
- 相机与拍立得素材：用于主题预览、角色档案和摄影整理提示。
- 蔷薇、蝴蝶、蝴蝶结等装饰素材：用于低干扰纹样、主题缩略图和加载失败回退图标。
- 周边展示图只作为视觉参考，不直接作为 APP 背景。

实施前需把使用到的角色图裁切为独立透明 PNG 或 WebP 资源，清除灰色/白色拼版背景。不得在运行时加载用户临时目录中的原图。

角色档案位于主题设置区域，包含：

- Hanabe 的摄影助手身份简介。
- 相机、蔷薇、蝴蝶与拍立得元素说明。
- 浅色和深色主题预览。
- “显示 Hanabe 小助手”总开关。

## 5. Hanabe 小助手

### 5.1 布局与状态

小助手默认停靠在主窗口右下角状态栏上方，不遮挡状态栏、滚动条、浮动操作按钮、检查器或照片选择区域。布局空间不足时，助手退化为紧凑状态；小窗口下只显示头像、任务名称和百分比。

状态模型：

- Hidden：用户关闭角色内容，不创建可见角色层。
- Idle：显示紧凑头像；点击可查看最近任务结果或摄影整理提示。
- Active：任务进行时展开进度气泡。
- Completed：短暂显示结果后自动回到 Idle。
- Failed：显示错误摘要和现有恢复入口，不自动收起。
- Cancelled：显示取消结果后回到 Idle。

### 5.2 进度内容

Active 状态按数据可用性显示：

- 当前任务名称。
- 完成百分比。
- 已处理文件数与总文件数。
- 已传输容量与总容量。
- 实时传输速度。
- 预计剩余时间。

小助手只消费现有任务进度来源。若速度、容量或剩余时间当前不可用，则隐藏对应字段，不推算或伪造数据。首期接入范围为已有进度来源能够覆盖的导入、复制、移动、扫描和 AI 识别任务；缺少统一进度来源的流程不为本主题新增业务状态。

### 5.3 显示控制

设置项“显示 Hanabe 小助手”控制角色插画、角色对话、角色档案动态内容和互动彩蛋。关闭后：

- 不显示角色头像或插画。
- 不显示角色式短句或摄影提示。
- 原有状态栏、进度条、通知和任务取消操作继续显示。
- 主题颜色和普通蔷薇装饰仍然生效，因为它们属于主题而非角色助手。

## 6. 状态文案与互动

文案保持简短、克制并与实际状态一致。例如：

- 空状态：“这里还没有照片，要从导入开始吗？”
- 扫描中：“正在整理照片线索…”
- 导入中：“正在把新的瞬间带进图库。”
- AI 识别：“正在辨认画面内容。”
- 完成：“整理完成，可以继续浏览了。”
- 取消：“任务已取消，已有内容不会被回退。”
- 错误：“这次没有完成，可以查看原因后重试。”

空闲头像点击后只显示最近任务摘要或一条本地内置摄影整理提示。不自动弹窗、不播放声音、不持续循环动画，也不引入网络角色聊天。

## 7. 组件边界与数据流

主题颜色继续由现有 `ThemeManager` 负责切换与持久化。角色助手使用独立的表现层状态适配器，将现有任务进度映射为统一的只读展示模型；它不执行导入、复制、移动、扫描或识别，也不拥有任务取消策略。

数据流：

`现有任务/进度来源 → 只读状态适配器 → Hanabe 助手展示模型 → WPF 角色助手视图`

建议组件责任：

- Hanabe 主题资源字典：定义主题原始色并接入现有资源组合。
- Hanabe 角色资源清单：管理裁切后的本地打包素材和状态映射。
- 助手展示模型：统一任务名称、状态、百分比和可选传输指标。
- 助手视图：负责停靠、紧凑/展开状态、动画和可访问性。
- 设置入口：负责主题选择与角色显示偏好。

实施时优先复用现有进度 ViewModel、设置持久化和共享控件。只有在现有契约无法表达多任务展示时，才增加最小只读适配层。

## 8. 动效与可访问性

- 只使用现有 Motion Token 允许的淡入、透明度变化、小幅位移和进度变化。
- 遵循系统减少动态效果设置；不得循环摇摆、闪烁或播放相机闪光动画。
- 助手头像和展开区域必须有可访问名称，状态变化通过克制的自动化通知表达。
- 键盘用户可以聚焦头像、展开内容、恢复操作和关闭按钮。
- 颜色不作为唯一状态信号；百分比、状态文字和图标共同表达进度。

## 9. 错误与回退

- 角色素材加载失败时回退到现有主题化相机或蔷薇矢量图标。
- 任务失败时展示来自现有流程的错误摘要，不泄露完整文件路径或内部异常堆栈。
- 多任务同时存在时，优先展示前台或最近活动任务；其余任务数量通过简短文本提示，详细管理仍由现有任务界面承担。
- 用户关闭助手、切换主题或调整窗口尺寸时，不中止或重启后台任务。

## 10. 验证计划

自动化验证：

- Hanabe Light/Dark 主题入口及资源键对称性。
- `ThemeManager` 切换和持久化。
- 角色显示开关持久化及 Hidden/Idle/Active/Completed/Failed/Cancelled 状态映射。
- 缺少速度、容量或剩余时间时的字段回退。
- 现有绑定、命令和事件处理器清单在 UI 改动前后保持一致。
- Release build、完整测试和 win-x64 publish 按 `docs/testing.md` 执行。

视觉与手工验证：

- Light/Dark 对比度以及 Hover、Pressed、Focus、Disabled 状态。
- 首页、图库、设置、导入和 AI 任务场景。
- 1440×900 最小支持窗口、常用 DPI、长中文和进度数字截断。
- 小助手与状态栏、浮动按钮、检查器、滚动条和照片选择区域不重叠。
- 角色开关关闭后所有核心进度与恢复操作仍可用。
- Loading、Empty、Error、取消、完成及多任务状态。

## 11. 非目标

- 不新增网络角色聊天、语音、声音效果或可下载角色包。
- 不让角色助手执行或改变业务任务。
- 不重构导入、传输、扫描或 AI 识别流程。
- 不在照片查看器或照片缩略图上覆盖角色水印。
- 不将整张用户拼版素材直接作为界面背景。
