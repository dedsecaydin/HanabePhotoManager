# 导入前日期文件夹批量确认设计

## 目标

照片来源分析完成后、任何复制或移动开始前，暂停导入并展示一次批量确认页面。用户可以浏览所有目标日期、填写备注，并在检测到同日期旧文件夹时明确决定新建、改名合并或沿用原名。确认完成后，导入直接写入预览中显示的最终文件夹。

本功能替代“分析完成后立刻自动复制”的行为，但保留独立的“日期文件夹”页面，供导入后的日常备注整理。

## 流程

1. 用户选择一个或多个来源文件夹，点击“开始分析与导入”。
2. 应用扫描媒体、分类并解析目标日期，不复制、不移动源文件。
3. 所有已选且日期已确认的媒体按目标日期分组，并扫描照片库中相同月日的现有文件夹。
4. 导入页进入“确认日期文件夹”阶段，一页展示所有日期分组。
5. 用户批量填写备注并处理已有文件夹冲突。
6. 只有全部可导入日期均得到有效目标后，“确认并开始导入”才可用。
7. 用户确认后冻结本次目标映射，生成导入计划并开始查重、复制、校验和可选源文件处理。

仍有未确认分类或日期的媒体继续沿用现有归属确认机制；日期文件夹确认不能绕过该门禁。

## 批量确认页面

页面位于现有导入工作区内，不打开连续对话框，也不跳转到独立“日期文件夹”导航页。页面支持键盘访问和垂直滚动。

每个日期分组显示：

- 只读日期，例如 `08.19`；
- 本组待导入媒体数量；
- 已检测到的同日期文件夹列表；
- 备注输入框；
- 处理策略；
- 最终目录名与完整目标预览；
- 行级验证或冲突提示。

底部提供：

- “返回修改来源”：退出确认阶段，不开始复制；
- “确认并开始导入”：在所有行有效时执行一次导入。

## 无现有文件夹

用户只需填写备注：

- 空备注生成 `MM.DD`；
- 非空备注生成 `MM.DD_备注`。

备注沿用日期文件夹服务的清理规则：去除首尾空白、重复日期前缀和开头分隔符，并把 Windows 文件名非法字符替换为下划线。页面预览必须使用清理后的真实名称。

## 已有同日期文件夹

页面先明确提示“该日期已有文件夹”。如果同日期存在多个文件夹，用户必须先选择本次操作所针对的旧文件夹。每一行独立选择以下策略：

### 1. 新建不同备注文件夹

- 保留所有旧文件夹不变；
- 用户必须提供能形成不同目标名的备注；
- 新目标不能与任何现有文件或文件夹重名；
- 新媒体导入新文件夹。

### 2. 修改原文件夹备注并导入

- 选择一个旧文件夹；
- 根据新备注预览目标名；
- 开始复制前先重命名所选旧文件夹；
- 重命名成功后，新媒体导入该文件夹；
- 若目标已存在、源消失或重命名失败，不开始本次导入，并保留可重试状态。

### 3. 使用原文件夹名

- 选择一个旧文件夹；
- 备注输入不改变磁盘名称；
- 新媒体直接导入所选旧文件夹；
- 最终预览显示原文件夹名。

页面不提供隐式默认策略。检测到旧文件夹后，用户必须明确选择，防止照片进入错误目录。

## 数据与职责

新增一次性“日期目标决策”模型，至少包含日期、媒体数量、现有候选目录、所选策略、所选旧目录、编辑备注、清理后备注、最终目标路径和验证状态。

目录扫描、名称清理和重命名继续复用 `LibraryDateFolderService`，避免产生第二套日期命名规则。导入计划构建接收已冻结的“日期 → 最终目录”映射，而不是再次根据日期自行推导目录。

视图模型负责：

- 从分析结果生成日期行；
- 响应策略、旧目录和备注变化；
- 计算预览与命令可用状态；
- 在用户确认时执行必要的预重命名；
- 只有所有预重命名成功后才启动导入。

## 一致性与错误处理

- 确认页面打开后若磁盘状态变化，确认时重新验证源目录和目标冲突。
- 多个“修改原文件夹”操作先全部验证，再依次执行；任何一步失败时不启动媒体复制，并逐行显示结果。
- 已成功执行的预重命名必须同步更新本次目标映射；若后续另一行失败，不回滚已成功重命名的目录，而是保留页面状态供用户修正并重试。
- 目标目录创建与现有查重流程使用同一冻结路径。
- 取消或返回发生在复制前，不创建目录、不移动媒体。
- 导入进行中禁止修改日期决策。

## 续传

待导入快照必须保存每个日期已确认的最终目标目录或等价稳定决策。应用恢复导入时不得重新猜测备注或改投另一个同日期文件夹。若恢复时目标已不存在，停止恢复并要求重新确认，不静默创建不同名称。

## UI 与可访问性

- 使用现有设计令牌、输入框、单选/选择控件和主次按钮样式；不创建页面级颜色。
- 日期和现有目录只读，备注是主要编辑字段。
- Tab 顺序按日期行从上到下，再到页面操作按钮。
- 策略名称使用完整中文，不只依赖编号或颜色。
- 浅色、深色及所有现有主题下，最终目录预览、错误文字和主按钮均须可读。
- 大量日期时只让列表区域滚动，底部确认操作保持可见。

## 测试与验收

自动化测试至少覆盖：

- 分析后进入确认阶段，未确认前不会调用导入执行器；
- 无旧目录时的空备注和非空备注目标；
- 三种旧目录策略各自生成正确最终路径；
- 同日期多个旧目录时必须选择具体目录；
- 新建策略的同名冲突；
- 重命名策略的成功、目标存在、源消失和 IO 失败；
- 非法字符与重复日期前缀清理后的预览和实际路径一致；
- 多日期批量确认与逐行独立策略；
- 返回、取消和失败时不复制媒体；
- 冻结映射被导入计划和续传共同使用；
- XAML 的只读日期、可编辑备注、滚动区域、键盘名称和主按钮可读性契约。

交互验收使用 D 盘一次性测试图库：至少三个日期，其中一个无旧目录、一个有单个旧目录、一个有多个旧目录；分别执行三种策略，确认开始复制前预览准确，导入后文件实际进入所选目录，并验证浅色/深色和键盘操作。

## 非目标

- 不允许修改日期本身；
- 不改变媒体分类和日期解析算法；
- 不自动合并多个既有同日期文件夹；
- 不删除旧文件夹；
- 不移除导入后的独立日期文件夹管理页；
- 不改动用户真实照片库作为测试数据。
