# Hanabe 最小化悬浮助手与来源备注设计

## 目标

1. 主窗口最小化后显示独立、置顶、可拖动的 Hanabe 任务悬浮窗；恢复主窗口后自动收回。
2. 导入时把来源文件名和导入前 SHA-256 写入目标媒体的 Windows“备注”属性，供同日期后续导入快速、可靠地确认重复内容。

## 最小化悬浮助手

- 新增轻量 WPF `Window`，复用当前 Hanabe 头像、主题资源以及主窗口 ViewModel 的任务名称、进度、剩余时间和传输状态。
- 主窗口进入 `WindowState.Minimized` 且 `ShowHanabeAssistant` 为真时显示悬浮窗；恢复为 Normal/Maximized 时隐藏。
- 悬浮窗置顶、无任务栏按钮、可在工作区内拖动；关闭按钮只隐藏本次悬浮显示，不退出主应用。
- 主窗口内现有助手仍保留；最小化时由独立悬浮窗接替，避免两个助手同时出现。
- 应用退出时显式关闭悬浮窗，避免遗留窗口或进程。

## 来源备注格式

使用 Windows Property System 的 `System.Comment`（资源管理器“备注”）写入一行可版本化文本：

```text
Hanabe:v1;OriginalName=DSC_1234.MP4;OriginalSha256=<64位十六进制>;OriginalLength=<字节数>
```

- 哈希必须在目标文件写入备注之前，针对未修改的来源内容计算。
- 字段值按明确的转义规则编码；解析器忽略未知字段，以支持后续扩展。
- 仅 Hanabe 前缀部分属于应用。若文件已有用户备注，则保留原内容并追加独立 Hanabe 行，不覆盖用户文字。
- 重复写入时更新既有 Hanabe 行，不重复叠加。

## 同日期重复检测

对当前导入文件，仅检查已确认的目标日期目录：

1. 规范化来源原始文件名，保留完整文件名并使用不区分大小写匹配。
2. 读取目录内文件的 Hanabe 备注；原始文件名不匹配的文件不进入该标识候选集。
3. 对匹配候选先比较 `OriginalLength`。
4. 计算新来源文件 SHA-256，并与备注里的 `OriginalSha256` 比较。
5. 名称、长度、原始哈希均相同，进入现有重复决策流程；同名但哈希不同则明确视为不同内容。
6. 无有效 Hanabe 备注的旧文件继续走现有“大小预筛 + 当前文件 SHA-256”流程，保持旧图库兼容。

## 写入限制与失败策略

- `System.Comment` 写入依赖 Windows 为具体扩展名注册的可写属性处理器。部分 RAW、视频、只读文件、网络目录或权限受限位置可能不支持。
- 写备注会改变目标文件字节、SHA-256 和通常的最后修改时间；重复判断因此使用备注保存的导入前原始哈希，不把写入后的目标哈希与来源哈希直接比较。
- 每次写入后必须关闭属性存储、重新读取并核对 Hanabe 行。只有回读一致才记录成功。
- 不支持或回读失败时不进行二进制层面的强制注入，不损坏文件、不删除目标；导入结果中显示具体失败原因，并保留现有文件名及旧式查重作为回退。
- 外部软件可能删除或改写备注；下次缺失时自然回到旧式查重。

## 组件边界

- `HanabeAssistantWindow`：只负责独立窗口视觉和拖动。
- 主窗口窗口状态协调：只负责显示、隐藏和生命周期，不复制业务进度。
- `IFileOriginMetadataStore`：读取/写入来源备注的抽象。
- Windows Property System 实现：封装 COM 属性存储、提交和回读验证。
- 来源元数据解析器：纯函数处理版本、编码、保留用户备注和校验。
- 导入重复预检：先使用来源备注缩小候选，再复用现有 SHA-256 与重复决策窗口。

## 测试与验收

- 纯单元测试覆盖备注序列化、解析、未知字段、用户备注保留、重复 Hanabe 行更新、损坏数据和大小写文件名。
- 导入测试覆盖相同 DSC/相同哈希、相同 DSC/不同哈希、不同 DSC、旧文件无备注、属性写入失败。
- UI 契约测试覆盖最小化显示、恢复隐藏、设置关闭时不显示以及悬浮窗拖动入口。
- 使用 D 盘临时 JPEG 与受支持的视频样本验证资源管理器可见备注、写入前后哈希变化及回读；对不支持格式验证安全失败。
- 最终执行 Release `/warnaserror` 构建、全量测试、自包含发布和新发布产物运行验收。
