# Hanabe 状态音效设计

## 目标

为 Hanabe 角色助手增加可切换的 A「相机机械」、B「Q 版提示」和 C「混合」三套状态音效，同时避免长任务、快速状态切换和逐文件进度造成声音骚扰。

## 用户设置

- 音效总开关，默认开启。
- 风格选择：相机机械、Q 版提示、混合；默认混合。
- 音量 0–100，默认 35。
- 安静模式：只播放完成和错误，默认关闭。
- A、B、混合分别提供试听；试听不受安静模式限制，但遵守总开关和音量。
- “重复检测完成后唤回主窗口”开关，默认开启。

## 状态映射

| Hanabe 状态 | A 相机机械 | B Q 版提示 | C 混合 |
|---|---|---|---|
| Idle | 无 | 无 | 无 |
| Scanning | 对焦扫描短音 | 探索短音 | 机械起音 + Q 版尾音 |
| Checking | 镜头锁定短音 | 双音确认 | 对焦 + 确认音 |
| Importing | 存储写入启动音 | 活跃启动音 | 机械启动 + Q 版尾音 |
| Completed | 柔和快门 | 成功铃音 | 快门 + 成功铃音 |
| Error | 低沉机械提醒 | 柔和警告音 | 简短混合警告 |

状态声音只在状态发生变化时播放。Idle 不播放；进度百分比变化不播放；相同状态在防抖窗口内不重复播放。安静模式只允许 Completed 和 Error。

## 架构

新增 `HanabeSoundPolicy` 负责纯逻辑决策与资源解析，新增应用级 `HanabeSoundService` 负责 WPF/Windows 音频播放、音量和防抖。`MainWindowViewModel.SetAssistantState` 继续作为唯一状态入口，在状态真正改变后通知服务。音效设置沿用 `AppSettingsStore` 与现有设置中心，不接触视频播放器的 LibVLC 音量。

音效使用应用内打包的短 WAV，全部为原创合成提示音，不依赖网络或外部版权素材。播放失败只静默跳过该次提示，不影响扫描、校验或导入业务。

## 重复检测完成唤回

重复检测成功且存在需要用户处理的重复项时，如果主窗口已最小化，应用恢复主窗口、激活并请求置前；Hanabe 独立浮窗随主窗口恢复而隐藏。没有重复项、检测取消、检测失败或主窗口本来就可见时不抢焦点。用户可在设置中心关闭该行为，继续仅由声音和浮窗提示。

## 验证

- 策略测试覆盖三种风格、安静模式、Idle、禁用和资源路径。
- 设置存储测试覆盖默认值与 JSON 往返。
- ViewModel 测试覆盖设置加载/保存与状态变化不重复触发。
- XAML 资源测试覆盖设置控件和试听命令绑定。
- 窗口策略测试覆盖开关、最小化状态、有无重复项、取消和失败。
- Release 构建、完整测试及发布内容检查确保 WAV 被复制。
